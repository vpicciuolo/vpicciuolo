## 🧠 OYYO

### One intelligence. One workspace. One place for everything.

**Made in UAE 🇦🇪 · Dubai-IT**

I am the **Founder and Technology Architect of [OYYO](https://oyyo.one)**, a proprietary AI workspace for bringing requests, models, specialist agents, company knowledge and useful outputs into one place.

The starting point is practical: a user should be able to describe the work in ordinary words. OYYO prepares the task brief, uses relevant context, selects eligible models and, where useful, coordinates specialist contributions, review and a clear final result. The goal is an experience that feels familiar while supporting more structured work behind the conversation.

**OYYO is available for private demos and private beta. [Request early access at oyyo.one/contact](https://oyyo.one/contact).**

| Area | Current documented scope | Explore |

| **Usable outputs** | Detailed drafts, specialist contributions, next actions and supported document exports; media generation and external actions depend on available tools | [Capability guide](https://github.com/vpicciuolo/oyyo-models/blob/main/docs/CAPABILITIES.md) |

Catalog counts describe available definitions, not simultaneous workers or a promise that every model is ready on every computer. Local models need compatible resources and successful device qualification. Optional connected assistance is a separate execution mode. A draft, plan or review is not evidence that a tool action or external publication occurred.

The documented Windows catalog baseline is **0.1.15**. Operating-system builds, device qualification and native application capabilities have their own scope; a catalog entry is not universal hardware or platform certification.

### Independent catalogs

The current task/style library can be refreshed through a manual **Sync catalog** control in compatible workspace builds, with validated local caching for offline use. [OYYO Catalogs](https://github.com/vpicciuolo/oyyo-catalogs) versions that content separately from application releases. This does not install executable tools or bypass model qualification.

### Where the engineering is focused

- Understanding the user's goal and preparing precise, task-specific briefs.
- Routing work to suitable eligible models with hardware and resource constraints in view.
- Coordinating roles independently of the model used for each assignment.
- Keeping memory, source material, reusable profiles and workspaces useful across daily work.
- Producing readable, detailed results with practical follow-ups and supported exports.
- Developing model engineering, local inference and multimodal workflows with explicit qualification and capability boundaries.

OYYO's core runtime, orchestration engine, internal prompts and proprietary development work remain private. Public catalogs explain product capabilities and selected engineering interfaces. Product names do not imply that third-party weights become OYYO-owned or remove applicable rights and notices.

### 🌐 [URL Metadata & Social Profile Fetcher](https://github.com/vpicciuolo/url-metadata-social-fetcher)

**URL in. Structured data out.**

Production-oriented TypeScript URL enrichment for websites, products, startups, apps, profiles, creators and social URLs.

Extract Open Graph and SEO metadata, titles, descriptions, images, favicons, canonical URLs, public social links, available profile metrics, JSON-LD and oEmbed data.

Designed with SSRF-safe server-side fetching and built using standard Web APIs with **zero runtime dependencies**.

The same class of technology is used in production systems including **BeHot.now** and **HORNO Network** services.

**Core areas:** TypeScript · URL Intelligence · Metadata · Open Graph · SEO · Social Discovery · Web Scraping · Security
